From the archives

Small discoveries.
Old code.

A few moments from the surviving source and CVS messages: progress, workarounds, refactoring, and a bug that waited for the restoration.

Dates describe preserved evidence. They do not always establish when a feature first existed.

01

“Finally a version that runs”

On 11 August 2002, a CVS message celebrates a small but recognisable milestone: “Finally a version that runs. Has a player and a monster. Player executes his soul and an ability.” It is a wonderfully direct progress report from the early object-and-ability architecture. This dates the recorded change, not the first time Iritor ever had a monster.

Source: iritor/components/gameobject.cpp r1.3 (2002-08-11)

02

A DirectX beta left a paper trail

The remembered beta-driver era has a concrete clue. On 26 August 2002, a math-header log says: “removed Hack with push ebx in CQuaternion::SQuadSetup, since Bug has been fixed in DX9 beta 2”. The preceding revision contains the register-saving workaround. That identifies a specific DX9 beta in this code path; it does not prove which SDK every other snapshot required.

Source: iritor/common/math/math3d_inline.h r1.6 (2002-08-26); iritor/common/math/math3d_inline.h r1.5 (2002-08-22)

03

The warning backlog gets a telling-off

A 16 January 2004 change cleans up warnings, with the unusually candid log: “finally removed a few warnings that hadn't been fixed for a long time - this is a bad habit, checking in code with warnings and then never getting rid of them!” Still familiar today.

Source: Iritor/UITest/inputTest.cpp r1.2 (2004-01-16)

04

A monolith, exactly at the origin

On 16 February 2004, a sample-world update announces: “further changed sample data file - now we've got a monolith at exactly (0;0;0)”. Among architectural work and bug fixes, the archive also preserves the small satisfaction of putting an object precisely where it belongs. This is a dated sample-data change, not the birth of monoliths in the game.

Source: sample-world data r1.5 (2004-02-16)

05

The rewrite has landmarks, not a known starting gun

The later CVS repository contains Iritor files from 28 October 2003. Its scene.cpp records “Refactored main() to work only with interfaces” on 14 November, “Refactored Physics and SceneManagement” on 16 November, and a larger message/terrain/movement change on 8 December. These establish the later architecture taking shape by autumn 2003. They do not tell us the exact day the team decided to restart, or prove all earlier code was deleted then.

Source: Iritor/Readme.txt r1.1 (2003-10-28); Iritor/Client/scene.cpp r1.1 (2003-11-14); Iritor/Client/scene.cpp r1.2 (2003-11-16); Iritor/Client/scene.cpp r1.7 (2003-12-08)

06

An object could leave its ID behind

The late client destroyed a scene object without removing its entry from the GUID-to-object map. Creating another object with that ID was then rejected as “Already used GUID”; another lookup could reach a stale pointer. The browser restoration adds the missing map erasure. This is a source-level bug in the preserved February 2004 client, not a claim that a particular historical play session hit it.

Source: Iritor/ClientLogic/Engine.cpp r1.19 (2004-02-11); Iritor/SceneManagement/Engine_impl.hpp r1.39 (2004-02-12)

07

Even a new architecture had an old friend

The later DirectPlay networking source greets its application identifier with “W007! The good old AppGUID of the original iritor client...” A small sign of continuity amid the architectural changes. The comment is present in the preserved 17 December 2003 revision; that is an evidence date, not a proven introduction date.

Source: Iritor/Toolkit/Network/Network_DirectPlay.cpp r1.4 (2003-12-17)

08

A sizeable history, counted honestly

The two preserved CVS histories index 31,105 file revisions in susi_cvs and 6,467 in flexo_cvs: 37,572 file revisions in total. These are not 37,572 commits. CVS versions individual files; one change can produce many revision records. The counts include the contents of those repositories—code, assets, documents and supporting material—and are not a count of original game-code changes or a measure of team productivity.

Source: indexed susi_cvs and flexo_cvs revision metadata.

These notes were checked against original RCS archives. The revision count was independently verified across all 14,675 archive headers. The full restoration preserves the detailed source references and counting method.
